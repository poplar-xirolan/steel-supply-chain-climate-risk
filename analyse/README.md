# Continuous scientific analysis

The numbered folders follow one processing chain; ABM and upstream reconstruction
are not separate projects. `library/steel_supply/` contains the shared algorithms.
All scripts use one workspace with sibling `data/`, `work/`, `result/` directories.
Only normal files/directories are used, with no symlinks or author-machine fallback.

## One full reconstruction workflow

The workflow starts from study-version normalized source tables and climate files
under `data/external/`, then computes all scientific stages and figure tables.
There is no input-mode option. `data/provided/` retains shared results and reference
data for comparison; no computed input is redirected to that directory.
Figure 3 boundaries and facility data are rebuilt from the source boundaries,
facility identities and newly computed losses. Source acquisition/preparation is
not automated; see `../DATA_ACCESS.md` for the reconstruction boundary.

## Commands

From this folder, using the environment installed as described in the root README:

```text
python run_analyse.py plan
python run_analyse.py check
python run_analyse.py run
python run_analyse.py run --resume
python run_analyse.py smoke
```

With no arguments, the entry point prints the plan and performs no calculations.
`check` is a read-only source-presence/environment check, not a claim that all
scientific values or complete ensembles have been validated.
Producing stages check scientific schemas, coverage and completion as they run.

`--from STAGE --to STAGE` selects an inclusive segment. A segment checks real
inputs on disk; it does not assume that an omitted earlier stage has run.
For example, a raw MFA-only reconstruction is:

```text
python run_analyse.py run --to mfa
```

`--workspace PATH` selects a **whole alternate workspace**. It must contain its
own `data/`; the program never falls back to the bundle's data if that is absent.
This permits a physically separate run, without links, and protects the original
project results. The code remains in this package; generated files go to the
selected workspace's `work/` and `result/`.

## Steps

| Folder | Work / output |
|---|---|
| `00_prepare_inputs/` | Explicit download helper; copy initial facility locations for extraction |
| `01_mfa/` | Trade cleaning, mapping, Fe-equivalent conversion, ore grade and 2023 MFA |
| `02_spatialization/` | Allocate national production to the three facility classes |
| `03_climate_extraction/` | Daily tasmax, tas, hurs, cyclone wind and wildfire extraction |
| `04_facility_hazards/` | Heatwave, cyclone and wildfire production losses |
| `05_country_constraints/` | National aggregation, cyclone availability and multi-hazard maximum |
| `06_dynamic_simulation/` | Weekly physical supply matching, inventories and scenario access rules |
| `07_dscci/` | Seven-stage adequacy/balance index and diagnostic numeric tables |
| `08_result_summaries/` | Annual/national/within-year outputs and actual-production summaries |
| `09_statistics/` | Country association and sensitivity analyses |
| `10_export_graphing_data/` | New numerical inputs for Figures 2–6 and Supplementary Figure 2 |

`config/stages.json` is the executable dependency graph. `config/scenarios.csv`
documents the same 411 commands generated by the shared scenario code; it does not
replace or loosen those scientific settings. `config/country_groups.json` records
the model-defined groups, not a claim about contemporary political membership.

## Completion, resumption and resource costs

Every completed stage records hashes of declared inputs, current package code,
scientific package versions and outputs. `--resume` rechecks that contract before
skipping work. Input, code, environment or output changes are not silently accepted.
Incomplete output is never labelled PASS just because files exist.

For a failed non-ABM stage, `--resume --retry-failed` is an explicit retry of an
unchanged pending contract; partial outputs are retained in `work/failed/`.
ABM retries use separate attempt directories and verify real per-step outputs.
Do not edit/delete receipts to reuse unrelated results; use a fresh workspace.

Full raw processing hashes its input contents for reproducibility; that operation
itself is costly for a multi-terabyte collection. A full run is not a quick smoke
test. There is no default download, full scenario launch, Git action or upload.

The miniature smoke case uses the actual ABM engine for 2023 with 7-day intervals,
including the final 1-day interval. It is synthetic and does not establish the
scientific validity of all full-scale results. Tests live entirely inside this
package and do not need the author's source checkout.

## Important preserved definitions

- DSCCI uses all **seven** stages. Combining steelmaking/casting in Figure 6d is
  display logic only; no index term is merged.
- Actual production, realized throughput, outbound deliveries and final demand
  are separate quantities. The plot interface uses `actual_output` for production.
- Unavailable cyclone inputs and invalid/missing wildfire coverage are not zero.
- Daily production weights, leap years, cross-year steps and the complete terminal
  step remain in the scientific calculations.
- The existing MFA M8→S1 ASU-FSP correction is retained.
- Legacy `e2eci` file/field identifiers are compatibility names for DSCCI, not a
  different index. Optional diagnostic rendering was omitted; numeric formulas
  were not rewritten to change the figures.

## Drawing the new results

Nothing in this workflow modifies `../graphing/`. Figure scripts accept explicit
new input paths. For example, from the package root:

```text
python graphing/plotting/Figure_5/plot_figure5.py --data-dir analyse/result/graphing_inputs/Figure_5 --output-dir analyse/result/redrawn/Figure_5
```

Figures 2 and 4 use `--data` with their CSV path; Figures 3, 5, 6 and Supplementary
Figure 2 use `--data-dir`. Install the separate graphing requirements for drawing.
Figures 1 and Supplementary Figure 1 are manually authored drawio sources.

## Validation and release status

The export was validated in an isolated Windows/Python 3.13.5 environment. The
single-full-workflow update passed the package tests and fresh original/export
comparisons: bounded five-stage MFA reconstruction, three weekly ABM cases and
all 411 scenario parameter vectors. Neither the full climate extraction nor the
411-scenario ABM grid was rerun.

See `data/DATA_DICTIONARY.md` and `../DATA_ACCESS.md` for data definitions and
source access. Code/data licences, persistent archive and DOI are pending author
release decisions; no licence or public deposit is fabricated here.
